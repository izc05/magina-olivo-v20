## 1. Estado Real de G2.3 y PR #766

La fase G2.3 implementa la cola de operaciones persistente local en Android (Room) garantizando:
- Reutilización de la infraestructura existente (`SyncOutboxEntity`, `SyncOutboxDao`, `OutboxWriter`, `DeliveryWriter`).
- Migración Room 26 → 27 con esquema exportado y versionado (`27.json`).
- Serialización canónica de payloads en formato JSON para inserción y actualización de pesadas (`DeliveryWriter`).
- Reglas estrictas de inmutabilidad de identificadores de operación: se conserva el `operation_id` en reintentos idempotentes idénticos; se genera un nuevo UUID ante cualquier mutación del payload, cuenta o versión base para prevenir alteraciones en vuelo.
- Diferenciación estricta de versiones: nunca se usa la versión local como sustituto de `remoteVersion` confirmada por el servidor.
- Respeto integral al consentimiento G1b: las operaciones sobre fincas revocadas se transicionan atómicamente a `BLOCKED` (abarcando estados `PENDING`, `FAILED` y `PROCESSING`).
- Preservación de operaciones `FAILED`: no se eliminan al colapsar nuevas operaciones locales.
- Las escrituras agrícolas locales se persisten sin importar el estado de consentimiento o sesión de cuenta (offline-first).

## 4. Observaciones Pendientes y Relevo para Codex

1. **Persistencia del ledger de consentimiento tras reinicio:**
   - Actualmente `revokeConsentForFarm` bloquea las operaciones en la base de datos Room (`sync_outbox`), pero el archivo JSON del ledger `AndroidFarmLinkLedger` no almacena entradas explícitas de revocación (únicamente `append` de nuevos consentimientos). En una siguiente fase se puede extender el ledger para registrar eventos de revocación persistentes en disco si se requiere auditoría forense offline.
2. **Atribución de cuenta en sesión activa:**
   - Al invocar `DeliveryWriter` y otros escritores, si no hay sesión activa o la finca no tiene cuenta vinculada, `accountId` se mantiene `null` y las operaciones permanecen estrictamente locales.
3. **Paso a G2.4 (Sincronización de Red):**
   - La red, HTTP y llamadas RPC a Supabase (`sync_own_delivery`, etc.) pertenecen a G2.4. La cola actual en G2.3 queda lista como repositorio local desacoplado.

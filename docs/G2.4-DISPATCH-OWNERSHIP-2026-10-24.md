## Ownership protocol

`DeliveryDispatchLease` uses one nonblocking OS file lock per canonical private directory.
Every conforming sender holds the same lease throughout claim, request settlement and
receipt persistence. A slow owner cannot be replaced because time elapsed. Process death
releases its OS descriptor; acquiring a lock does not itself assert any remote outcome.

A JVM registry prevents opening/closing a second descriptor while this JVM owns the file:
some systems release process locks when another descriptor for the file closes. Canonical
paths share this registry. Never delete or rename the lock file to recover ownership.

`claimDeliveryRecoveryWithLease` atomically claims the old FAILED operation and persists a
versioned marker bound to the canonical lock path hash. The same directory/lease must be
used across all accounts and instances for that operational database. Wrong-directory
leases cannot reclaim its marked requests. No tokens or agricultural payloads are stored
in the lock file.

After reacquisition, `recoverAbandonedDeliveryClaim` changes only a matching marked
PROCESSING request to FAILED/OUTCOME_UNKNOWN. UUID, payload, base version and attempt
count are preserved. Query the authenticated operation receipt or retry the exact request;
never treat process death as proof that the server rejected it. Unmarked legacy PROCESSING
rows are not adopted automatically. Account/farm bindings and fresh authorization remain
mandatory; local callbacks are not authentication or permission to send HTTP.

## Verification and limits

- Six original ownership tests first failed against the placeholder; implemented locking
  then passed, followed by a seventh durable-namespace regression.
- Standalone JUnit with JDK17/Kotlin 2.3.0: seven ownership tests PASS, including a real
  second JVM, a durable PID checkpoint, denial while it is alive, forced termination,
  confirmed exit and successful lock reacquisition. This is JVM process-death evidence,
  not an Android force-stop or a complete request/Room recovery test.
- Ten SQLite regressions execute SQL extracted from the production DAO, including
  durable marker isolation and preservation/retry of the uncertain operation.
- Two additional Room tests cover handoff, denied consent, wrong namespace, unchanged
  kilos/payload/UUID and rejection of unmarked PROCESSING. Android execution pending on
  the new SHA. Standalone Kotlin 2.3.0 does not replace project Kotlin 2.4.20 CI.

No active HTTP dispatcher or app lock-directory factory is installed. Before activation,
bind one fixed private no-backup directory to the operational DB, route ALL send/recovery
paths through this lease, hold it until network cancellation actually settles, coordinate
Auth/revocation and run Android force-stop plus request/replay tests. A caller bypassing
this protocol is not made safe by these local APIs. No Room schema change, remote
deployment, main merge or distributable candidate is introduced.
